# Морской бой: сервис и арена

Реализация включает REST-сервис с хранением игровых сессий в PostgreSQL и тонкую арену, которая запускает игру двух сервисов, ведёт очередь, проверяет честность ответов и присуждает техническое поражение при нарушении протокола.

Полное описание устройства, API, состояния сессий и проверок арены: [docs/architecture.md](docs/architecture.md).

## Запуск

```bash
docker compose up --build -d
docker compose run --rm service-a alembic upgrade head
docker compose run --rm service-a python -m arena.main http://service-a:8000 http://service-b:8000
```

Для разработки миграции создаются через `alembic revision --autogenerate -m "описание"`, а тесты запускаются командой `pytest`.

Первый ход выбирается ареной случайно. При `hit` или `killed` ход остаётся у атакующего; при `miss` переходит сопернику.

## Проверки арены

- каждый запрос имеет лимит в одну секунду;
- `/games` обязан вернуть UUID и легальную классическую расстановку: `1×4, 2×3, 3×2, 4×1`, без касаний, в том числе диагональных;
- выстрел обязан быть уникальной координатой `A1`–`J10`;
- результат защиты сверяется с опубликованной расстановкой и всеми ранее принятыми выстрелами;
- невалидный ответ, HTTP-ошибка, таймаут, повторный выстрел или нечестный результат означают техническое поражение.

Конец партии определяет арена: она считает 20 палуб кораблей противника. После этого она вызывает `/close` у обоих сервисов.
